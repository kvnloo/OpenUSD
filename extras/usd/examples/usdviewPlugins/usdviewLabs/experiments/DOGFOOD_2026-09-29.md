## Findings

### Real Usd.TimeCode frame

`usdviewApi.frame` is `Usd.TimeCode` in the packaged runtime. Calling
`float(usdviewApi.frame)` raised `TypeError`.

A `GetValue()`-aware fix made `what frame am I on` return `0.0`.

Follow-up: #14.

### Cancel closed the mutable preview

Cancellation safely destroyed the preview before stale Accept could be clicked.
That proves execution safety but does not exercise the explicit blocked-Accept
UX from the P3 contract.

Follow-up #14 keeps stale action previews visible and click-testable while the
generation gate still prevents execution.

### Qt poll coalesced accepted events

The socket-thread GenerationGate updated correctly, but the Qt poll drained its
queue and acted on only the latest message. A cancel/final pair in one poll
window could therefore lose a receipt/UI event.

Follow-up #14 processes accepted lifecycle events FIFO.

## Rendering environment

Native Wayland produced an OpenGL ES context; Storm requires desktop OpenGL
4.5.

Per-process `QT_QPA_PLATFORM=xcb` switched to GLX and let usdview run on the
isolated headless output, but Storm rendered a flat red viewport and logged
`Attempt to retrieve context when no valid context` during startup.

This resembles existing upstream issue families:

- OpenUSD #2043 — shader compilation/context errors, including the same
  "Attempt to retrieve context when no valid context" message
- OpenUSD #2009 — similar shader/context failure
- OpenUSD #2756 — HgiGL minimum OpenGL 4.5 requirement

This is tracked separately from Labs routing/safety logic.
